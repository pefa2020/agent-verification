# Agent Verification v2.6 — Evidence Integrity Gap Analysis

## Scope

v2.6 hardens the evidence boundary established by v2.5. It adds deterministic evidence digests, run-bound replay protection, and an append-only hash-chained verification ledger.

## Targeted properties

| Replay protection | OPEN | COVERED |
| Evidence integrity digest | OPEN | COVERED |
| Run binding | OPEN | COVERED |

## Design boundary

The v2.6 ledger is an in-memory integrity primitive. SHA-256 detects accidental or post-hoc modification of the represented evidence/history, while the ledger rejects duplicate `(run_id, evidence_digest)` pairs. This is not a cryptographic authenticity system: without an external trust root or signature, it does not prove who produced the evidence.

The implementation intentionally avoids persistence, distributed coordination, signatures, key management, or real-agent integration. Those remain future work.

## Adversarial guarantees

- Equivalent JSON objects have the same canonical digest.
- Mutating evidence changes its digest.
- The same evidence cannot be appended twice to a run.
- Each record is sequence-numbered.
- Each record commits to the previous record digest.
- Reordering, sequence mutation, or record tampering causes ledger verification to fail.

## Release discipline

v2.6 starts from the released v2.5 commit. It does not modify `main` or reintroduce the retired v1.6 AWS infrastructure. Passing tests demonstrate implemented behavioral guarantees; they are not a formal security proof.
