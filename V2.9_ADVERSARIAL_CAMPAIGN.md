# Agent Verification v2.9 — Adversarial Campaign

## Objective

v2.9 attacks the complete control boundary established through v2.4–v2.8.
The goal is not to add agent capability. The goal is to attempt to violate the
invariants that keep model requests, tool execution, evidence, and DFA state
under verifier control.

## Campaign targets

- malformed model tool-call JSON;
- non-object model arguments;
- unknown tools;
- tool failures and state preservation;
- tool requests before `BUILD`;
- tool requests after `COMPLETE` or `ABORTED`;
- autonomous continuation after `USER_REQUIRED`;
- replayed evidence;
- mutated evidence and digest divergence;
- tampered evidence-ledger history;
- reordered ledger records;
- duplicate ledger sequence numbers;
- malformed evidence that could otherwise influence verification;
- direct attempts to skip DFA states;
- end-to-end completion followed by terminal-state enforcement.

## Core invariant

> An agent may request an operation, but untrusted model output must never become authorization, verification evidence, or an uncontrolled DFA transition.

## Scope boundary

v2.9 is an adversarial regression campaign, not a formal security proof.
It does not claim resistance to every possible attack, cryptographic authenticity
of external events, or production-scale security. It specifically verifies that
known attack classes against the existing v2.4–v2.8 interfaces remain contained.

## Release discipline

- v2.8 remains immutable.
- v2.9 starts exactly from the v2.8 release commit.
- Deterministic adversarial tests must pass locally and in GitHub Actions.
- No AWS infrastructure, credentials, network tools, or arbitrary code execution
  are introduced merely to expand the test surface.
