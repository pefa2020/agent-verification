# Agent Verification v2.8 — Real LLM Integration

## Objective

v2.8 adds an optional live OpenAI Responses API adapter so a real model can request verifier-owned tools through the existing v2.7 runtime.

## What is tested

- A model response containing a function call is converted into the existing `ToolRequest` boundary.
- The verifier-owned runtime, not the model, executes the tool.
- Unknown or denied requests remain rejected by the runtime.
- Tool execution remains constrained by DFA state.
- Deterministic adapter tests run without network access.
- An opt-in live test can exercise a real model when `OPENAI_API_KEY` is supplied.

## Security boundary

The model receives tool descriptions, but it does not receive the runtime, DFA controller, tool registry, or authorization authority. The adapter translates model output into a request and submits that request to `AgentToolRuntime`.

## Non-goals

v2.8 does not claim that an LLM is safe, reliable, truthful, or production-ready. A successful live test demonstrates only that a real model can emit a tool request that is intercepted by the existing deterministic boundary.

## Live run

Install the optional dependency with `python -m pip install openai`, set `OPENAI_API_KEY`, and optionally set `AGENT_VERIFICATION_MODEL`. Run the explicitly marked live test with `python -m pytest -q -m live` after adding the marker configuration if desired, or select the test directly with `python -m pytest -q tests/test_llm_agent_runtime.py -k live_openai`.

Credentials must never be committed to the repository or embedded in deterministic CI.
