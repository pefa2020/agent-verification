# Agent Verification v2.5 — Adversarial Verification Gap Analysis

## Purpose

v2.4 established a deterministic verification/control core and released it with the existing regression suite passing locally and in GitHub Actions. v2.5 hardens the boundaries that v2.4 already exposes and makes the remaining verification gaps explicit.

## What v2.4 already proves

- Explicit DFA states and transitions are executable.
- Invalid non-terminal transitions raise an error instead of silently advancing.
- Terminal states are absorbing.
- Verification evidence has a required schema and mandatory criteria.
- PASS/FAIL/BLOCKED evidence must be internally consistent with its criteria.
- Recoverable failures are bounded by a retry budget.
- Interpretation drift and blocked verification stop autonomous continuation.
- User intervention is explicit; clarification requires non-empty instruction.
- Cancellation and abort produce terminal ABORTED behavior.
- The end-to-end regression suite passes 62/62 in the v2.4 release baseline.

## v2.5 scope decision

The first v2.5 increment is deliberately narrow: **adversarial boundary regression testing**. It does not claim to solve replay attacks, cryptographic authenticity, or real-agent integration. Those require additional design decisions and evidence.

The adversarial suite adds explicit coverage for illegal transitions, terminal-state mutation, malformed evidence types, and malformed execution identifiers. GitHub Actions executed the complete suite for commit `6defa165820c81d8e32234a867adaf640f3a8d40` and reported **82 passed in 0.15s**.

A v2.5 release should only be promoted after the new adversarial tests pass locally and in GitHub Actions, with the v2.4 release left immutable.

## Release discipline

- `main` remains the released v2.4 baseline.
- `v2.5` is the development branch and starts exactly from v2.4.
- No AWS infrastructure is reintroduced merely to make v2.5 green; v2.4 intentionally has no `infra/` tree.
- Passing tests establish implemented behavioral guarantees; they do not constitute a formal security proof.
