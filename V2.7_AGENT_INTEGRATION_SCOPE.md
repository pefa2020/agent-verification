# Agent Verification v2.7 — Agent/Tool Integration Scope

## Purpose

v2.7 adds a deterministic agent/tool execution boundary around the existing DFA verifier.
The agent may request named tools, but the runtime—not the agent—controls whether a tool call is legal.

## Guarantees demonstrated

- Tool execution is denied before the DFA reaches `BUILD`.
- Unknown tools are rejected explicitly.
- Tool exceptions become explicit failed results rather than uncontrolled state changes.
- Evidence submission is denied outside `VERIFY`.
- Verification evidence drives the existing DFA transition into `COMPLETE`, `BUILD`, or `USER_REQUIRED`.
- Terminal `COMPLETE` and `ABORTED` states prevent further tool execution.
- Evidence is recorded through the v2.6 integrity/replay ledger.
- The agent cannot bypass the DFA by issuing a tool request directly.

## Deliberate scope boundary

This is a deterministic integration harness, not a claim of production-grade LLM integration.
It does not introduce network tools, arbitrary code execution, credentials, or autonomous external side effects.
The tool registry is explicitly supplied by the caller and remains under the verifier's control.

## Verification target

The important invariant is:

> An agent can request an action, but it cannot authorize its own execution or advance verification state outside the DFA.

v2.7 therefore establishes the controlled seam where a future real agent/tool implementation can be attached without replacing the verification boundary.
